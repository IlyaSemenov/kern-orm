# Empty changes and `none()`

An `upsert` without values and an `insertMany` without records reject, as [values](../architecture/mutations.md#values) and [upserts](../architecture/mutations.md#upserts) of architecture/mutations.md state; an `update` without values changes no row and resolves as the update would.
Two independent goals:

1. Take them as changing nothing, so that code that passes the values of a request, such as of a PATCH, needs no check such as `if (Object.keys(values).length > 0)` before `upsert`.
   - An `upsert` without values, such as of the empty values of a PATCH, changes no value of an existing record: after it, the record of the key exists and is returned, and a missing record is inserted with its defaults.
     - An update of the key, `ON CONFLICT (key) DO UPDATE SET <column of the key> = EXCLUDED.<column of the key>`, returns the record atomically in every case, but updates an existing row physically: it fires `UPDATE` triggers, such as of `updated_at`, locks the row, and writes a new version of it.
       The upsert of the row of a [singleton table](../architecture/queries.md#queries-of-a-singleton-table) has no column of a key to set this way.
     - A select after `DO NOTHING`, `WITH inserted AS (INSERT ... ON CONFLICT DO NOTHING RETURNING ...) SELECT ... FROM inserted UNION ALL SELECT ... FROM <table> WHERE <key> AND NOT EXISTS (SELECT FROM inserted)`, leaves an existing row untouched, but its `SELECT` misses a record that a concurrent transaction inserted after the statement started, so it returns no row and rejects with `NotFoundError`.
     - Orchid ORM 1.78.47 turns `upsert` without the values of the update into `orCreate`: a `SELECT`, and then an `INSERT ... WHERE NOT EXISTS` in a second statement, which rejects with a unique violation when a concurrent transaction inserts the record between them ([source](https://github.com/romeerez/orchid-orm/blob/3302410cb48b02e7c65dec837862bc33250254fd/packages/pqb/src/query/basic-features/mutate/upsert.ts#L47-L66)).
   - An `insertMany` without records changes no row: the number `0`, or an empty array of the selected fields.
2. Skip the statement when its result is known without the database: a filter of `FALSE`, such as of `in([])`, or an `insertMany` without records resolves to no rows without a roundtrip, as a query of rows of `none()` and an update and a delete of its rows do ([queries of a Db](../architecture/queries.md#queries-of-a-db)).
   - Orchid ORM 1.78.47 resolves a query of `whereIn` of an empty list without querying the database ([docs](https://github.com/romeerez/orchid-orm/blob/3302410cb48b02e7c65dec837862bc33250254fd/docs/src/guide/where.md#wherein)), and code that filters by a list from a request relies on it.
     Rails resolves the records of a condition of an empty list without a query ([source](https://github.com/rails/rails/blob/v8.1.4.1/activerecord/lib/active_record/relation.rb#L1465-L1466), [source](https://github.com/rails/rails/blob/v8.1.4.1/activerecord/lib/active_record/relation/where_clause.rb#L99-L107)), and Django a filter of `__in` of an empty list, whose compilation raises `EmptyResultSet` ([source](https://github.com/django/django/blob/6.0.10/django/db/models/lookups.py#L535-L536)).
   - An aggregate query and a query of `exists` of `none()` run their statement, which returns one row: decide whether to resolve them without it, such as `count` to `0` and `exists` to `false`, while a fallback of `coalesce` may be an expression that only the database evaluates.
     - Orchid ORM resolves `count` of `none` to `0` and another aggregate to `null` without a query, and resolves a grouped aggregate, a window function, and an aggregate compared by an operator as not found ([source](https://github.com/romeerez/orchid-orm/blob/3302410cb48b02e7c65dec837862bc33250254fd/packages/pqb/src/query/extra-features/none/none.ts#L11-L34)).
     - Rails resolves `count` and `sum` of `none` to `0`, and `average`, `minimum`, and `maximum` to `nil`, or each to an empty hash after `group`, without a query ([source](https://github.com/rails/rails/blob/v8.1.4.1/activerecord/lib/active_record/relation/calculations.rb#L216-L228)).
     - Django resolves `aggregate` of `none` without a query only when every aggregate has a value over no rows, such as `0` of `Count` and `None` of `Sum`, and runs it with `0 = 1` otherwise ([source](https://github.com/django/django/blob/6.0.10/django/db/models/sql/query.py#L628-L640)).
   - `toSQL` and `$compile` of a query of `none()` give its statement, which filters by `FALSE`; decide what they give for an `insertMany` without records, which has no statement.
